# Accessibility

What the app is checked against, how, and what is left for a person to check. Added in [5.2] (#46).

## Standard

WCAG 2.1 level AA, in both themes: text contrast at least 4.5:1, every control reachable and usable by
keyboard with a visible focus ring, and a name for every control, icon button and chart that a screen reader can
read out.

## Automated checks (run in CI, `e2e` job)

| Test | What it checks |
|---|---|
| `e2e/a11y.spec.ts` | [axe-core](https://github.com/dequelabs/axe-core) with the `wcag2a`, `wcag2aa`, `wcag21a` and `wcag21aa` rules on sign-in, every main screen, every "new …" form, Savings, Debt, a transaction's detail screen and the month report. That includes colour contrast, names for buttons, links, images and form fields, landmarks, heading order and ARIA use |
| `e2e/keyboard.spec.ts` | Tab through every main screen (up to 80 stops) without Enter or Space: Tab must reach the controls, never get stuck, and every control it lands on must draw a focus ring (outline or box shadow) |

Both run in the two Playwright projects, phone width in light mode and desktop width in dark mode, so each
theme is covered. A failing axe check lists each problem in the CI log (`rule (impact): element — what is
wrong`) and attaches the full axe result to the `e2e-report` artifact.

To add a screen to the checks, add its path to the `screens` list in both files.

## What the first run found and fixed

| Problem | Where | Fix |
|---|---|---|
| Unselected segmented options on the page header: 4.49:1 | Every screen with a Segmented control on the header (light) | `--color-on-header-muted` `#dce3ec` → `#e1e7ef` (4.6:1) |
| Orange status pill text: 4.16:1 | Bills, "Due in 2 days" (light) | `--tone-orange-text` light `#b4541a` → `#a34a15` (4.9:1) |
| Green "✓ Matches SMS" on the page background: 3.84:1 | Debt (dark) | `--tone-green-text` dark `#05da93` → `#5ee8b0` (4.6:1) |
| Report hint and status lines in grey on the header colour: 1.22:1 | Month report (screen only, not the PDF) | They use `--color-on-header-muted`, because the report sits outside the shell on the header-coloured body. The "No spending" line inside the paper sheet keeps the muted text colour (`.sheetEmpty`) |

The keyboard pass found no control without a focus ring. The one stop that looked like one was the calendar button
inside date and month inputs, which the browser draws itself; the test skips it.

## Keyboard notes

- The PIN pad takes digits from the keyboard as well as taps.
- Native date and month inputs use the browser's own keyboard handling (arrow keys change the value).

## Left for a person

These need a real device and are in the owner's iPhone checklist ([5.1], `docs/DEVICE-CHECKLIST.md`):

- VoiceOver: swipe through Overview, Add transaction and Settings; every item is read out with a sensible name.
- Larger text (Settings → Display → Text size): screens still fit and nothing is cut off.
- Reduce motion and both themes on the phone.
